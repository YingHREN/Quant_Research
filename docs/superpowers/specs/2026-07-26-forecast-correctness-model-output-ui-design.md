# 预测口径修正与模型输出决策面板设计

## 1. 目标

第一阶段同时解决两个问题：

1. 修正生产预测与离线研究之间不一致的标签、执行价格和基线口径；
2. 在股票详情页按模型独立展示输出，使用户能够区分原始预测、风险状态、上涨结构和最终决策。

本阶段不承诺提高收益，不把规则分数解释为概率，也不增加会改变 K 线时间轴、价格轴或图表布局的预测图层。

## 2. 信息边界

- 观察日为交易日 `t`。
- 日线模型只能使用 `t` 日收盘前已知的数据。
- 可执行收益标签统一为：`t+1` 交易日开盘进入，持有至第 5、20 或 60 个未来交易日收盘。
- 训练样本的标签结束日期必须严格早于预测观察日。
- 缺少下一交易日开盘价、目标日收盘价或完整执行区间的样本不得进入训练或评估。
- 历史锁定日期展示的所有模型输出必须来自该日期的点时计算，不得用今天的风险或板块状态解释过去。

## 3. 模型分层

### 3.1 主预测

生产主预测仍为 `ridge_direction_v1`，但标签统一为下一交易日开盘至未来目标日收盘的可执行收益。

主预测输出：

- 模型名称和版本；
- 预测周期；
- 原始预测收益；
- 原始方向；
- 训练样本数；
- 训练标签截止日期；
- 校准状态；
- 与基线比较后的证据状态。

直接方向 Logistic、浅层 Boosting 和近期加权动量属于挑战模型。只有完成点时走步评估并通过晋级门槛后，才能标为生产模型；否则 UI 只显示“研究中”或“未晋级”及最近一次评估结论。

### 3.2 向下风险

分别展示，禁止合并成一个无法解释的总概率：

- 8 项当日向下确认；
- 12 项个股风险及其记忆状态；
- 板块宽度与成交量压力状态；
- 持续阴跌状态；
- 后续的宏观风险和盘中订单流状态。

每个模型输出原始分数、记忆后分数、状态、记忆年龄、实际触发条件和模型版本。分数统一标记为规则评分或状态强度，不标记为概率。

### 3.3 向上结构

分别展示：

- 三条件结构转强；
- 四条件向上早期观察；
- 严格 VCP；
- 紧密平台；
- 后续需求确认模型；
- 后续历史 VCP 突破和 Pocket Pivot。

结构模型只能增加“准备度”或“观察”证据，不能直接覆盖已确认的向下风险。

### 3.4 最终决策

`forecast_decision_policy` 输出：

- 最终方向；
- 决策动作：保留、降为中性、覆盖为下跌；
- 风险状态；
- 调整原因；
- 参与决策的风险来源；
- 策略名称和版本。

最终决策必须与 Ridge 原始输出并列显示。发生调整时，UI 使用一句完整说明，例如：

> Ridge 原始预测上涨；板块持续风险较高且当日破位确认达到阈值，最终覆盖为向下风险。

## 4. 统一模型输出契约

现有 forecast 合约保持兼容，并为每个日期、每个周期增加可扩展的 `model_outputs`：

```text
model_outputs:
  primary:
    - key
      version
      kind: statistical_forecast
      lifecycle: production | shadow | research | planned
      status: available | unavailable | not_promoted
      value
      direction
      timing
      evidence_status
      explanation
      limitations
  downside:
    - key
      version
      kind: rule_score | remembered_state
      lifecycle
      score
      raw_score
      state
      memory_age_sessions
      conditions
      timing
      explanation
  bullish_structure:
    - key
      version
      kind: shape_state | rule_score
      lifecycle
      score
      state
      conditions
      timing
      explanation
  decision:
    key
    version
    kind: decision_policy
    final_direction
    action
    reasons
    explanation
```

通用约束：

- `kind` 决定 UI 用“预测”“规则评分”“状态”还是“决策策略”描述；
- `lifecycle` 明确生产、影子、研究和计划状态；
- 只有通过样本外校准门槛的统计模型可输出概率；
- `timing` 必须为盘中、收盘确认或下一交易日可执行之一；
- 缺失值必须附带机器可读原因，不能默认视为中性；
- 新增模型通过注册表加入，不要求修改图表核心代码。

## 5. UI 布局

模型输出决策面板放在 K 线及日期详情下方、因子总览上方。

### 5.1 顶部摘要

固定展示四项：

- 最终方向；
- Ridge 原始方向和收益；
- 当日向下确认分；
- 最高持续风险来源、分数和记忆年龄。

### 5.2 模型卡片

使用四组可折叠卡片：

1. 主预测模型；
2. 向下风险模型；
3. 向上结构模型；
4. 最终决策策略。

每张卡片必须显示模型类型和生命周期标签。默认展开最终决策和异常模型；正常或未触发模型保持紧凑。

### 5.3 历史日期交互

- 自由悬停只更新临时模型面板，不改变图表范围；
- 点击锁定后，向下滚动、移出图表或移动鼠标不得改变日期；
- 只有再次点击图表或显式解除锁定才允许切换日期；
- 模型卡片更新不得增加未来时间点、改变价格轴或触发图表重新适配；
- 请求中的加载状态必须保留面板尺寸，避免内容出现时页面抖动。

### 5.4 本地化与解释

中英文均提供：

- 模型名称；
- 一句话直觉解释；
- 输入类别；
- 输出含义；
- 实际值和阈值；
- 当前为何触发或未触发；
- 主要限制。

所有规则卡片统一显示“规则分数，不是概率”；所有未通过晋级门槛的统计模型显示“尚未证明预测优势”。

## 6. 基线与评估

每个周期至少比较：

- 零收益基线；
- 扩展窗口历史均值基线；
- 始终上涨方向基线；
- 当前生产 Ridge；
- 已实现的方向分类挑战模型。

同时报告：

- 覆盖率；
- MAE、RMSE；
- 平衡准确率和 Macro F1；
- 上涨/中性/下跌的精确率与召回率；
- 分方向实际收益；
- 最大不利波动；
- 非重叠样本结果；
- 全股票池、半导体、软件和市场状态分组结果。

任一周期未稳定超过预先指定基线时，UI 只能展示研究结果，不得显示“可靠”“高置信度”或概率措辞。

## 7. 实施边界

本阶段包括：

- 预测标签与执行口径统一；
- 基线和证据状态；
- 统一模型输出契约；
- 股票详情模型决策面板；
- 中英文解释；
- 点时历史回放；
- API、渲染和交互回归测试。

本阶段不包括：

- 扩充 8～10 年数据本身；
- 训练新的 Attention 模型；
- CAN SLIM 基本面和 13F；
- 盘中逐笔和报价；
- 历史 VCP/Pocket Pivot 图标；
- 持仓卖出状态模型。

## 8. 验收

- 生产 Ridge 与离线评估使用完全相同的下一交易日开盘执行标签；
- 5/20/60 日均展示基线和证据状态；
- 每个当前模型均在独立卡片中输出或明确显示不可用/研究中；
- 规则分数不显示为概率；
- Ridge 原始结果与最终策略结果始终并列；
- 锁定历史日期后模型面板保持同一日期；
- 模型输出更新不改变图表可视范围、价格轴或页面高度；
- 中英文名称、解释、实际值、阈值和版本完整；
- 前缀不变性、API 合约、交互和完整自动化测试通过。
