# 盘中实时订阅与看板设计

## 目标

在现有 Alpaca 免费 IEX 逐笔与报价采集基础上，让用户在股票池中选择需要实时
跟踪的股票，并在个股页面查看可解释的盘中价格、成交量和买卖压力证据。

本功能只用于研究。IEX 是部分市场覆盖，买卖压力是由成交方向与最优买卖报价推断的
证据分数，不是全市场订单流、收益概率或交易建议。

## 当前基础

项目已经具备以下能力：

- 供应商无关的逐笔、报价、纠错和撤销事件契约；
- Alpaca 免费 IEX WebSocket 适配器和动态订阅更新；
- 固定最多 30 个代码的优先级订阅池；
- SQLite 逐笔、报价、纠错、撤销、订阅区间和采集器状态存储；
- 独立采集进程的心跳、断线重连和只读状态 API。

尚缺少浏览器到采集进程的跨进程订阅控制、分钟聚合 API，以及实际的实时 UI。

## 订阅规则

`SPY`、`QQQ`、`SOXX` 是固定市场参考代码，始终占用 3 个订阅名额，用户不能移除。
Alpaca IEX 当前总上限保持 30，因此用户最多选择 27 只股票。

用户选择持久化到盘中 SQLite 数据库的控制表。控制记录包含单调递增的 revision、
标准化后的用户代码列表和 UTC 更新时间。HTTP API 只修改期望状态，不直接访问
Alpaca。

独立采集进程每秒检查一次 revision。revision 变化后调用现有
`IntradayCollector.set_selection()`，由 provider 在当前 WebSocket 上先订阅新增代码、
再取消旧代码。采集器确认后继续通过现有状态表发布实际确认代码。

API 必须同时返回：

- `requested_symbols`：用户要求的代码；
- `confirmed_symbols`：Alpaca 已确认的代码；
- `pending_symbols`：尚未确认的差集；
- `fixed_symbols`、用户名额和剩余名额；
- collector 状态、覆盖范围、最后事件时间和安全错误码。

页面不能把“已保存选择”显示成“已接收实时数据”。

## HTTP 接口

### 订阅状态

```text
GET /api/market-data/subscriptions
```

返回固定代码、用户代码、请求/确认/等待代码、容量和采集状态。

```text
PUT /api/market-data/subscriptions
Content-Type: application/json

{"symbols": ["NVDA", "AMD", "SNDK"]}
```

该操作是原子替换。代码沿用项目股票代码校验规则；重复代码去重；固定代码不计入
用户输入；超过 27 只返回稳定的 `subscription_limit_exceeded` 错误，不部分保存。

### 个股盘中快照

```text
GET /api/intraday/<ticker>?window=120
```

`window` 表示最近分钟数，服务端限制在安全范围内。响应包含：

- 订阅状态和 IEX 覆盖说明；
- 最近一笔成交及其事件时间；
- 最近最优买价、卖价、价差和报价时间；
- 最近交易日的 1 分钟 OHLCV；
- 每分钟主动买量、主动卖量、未知方向量和成交 Delta；
- 当前窗口的压力分数、证据覆盖率和数据新鲜度；
- `live`、`stale`、`market_closed`、`pending`、`not_subscribed`、
  `collector_disconnected` 或 `unavailable` 状态。

分钟聚合必须尊重已保存的成交纠错与撤销。没有报价或无法判向的成交进入
`unknown_volume`，不能为了凑分数强行归到买方或卖方。

## 买卖压力

现有采集器已经保存 `buy`、`sell` 和 `unknown` 成交方向。第一版压力分数只使用：

- 有方向成交量 Delta；
- 有方向成交量占总成交量的覆盖率；
- 最近若干分钟价格变化与 Delta 是否一致；
- 当前价差和报价新鲜度。

分数范围为 `-100` 到 `100`：负值表示主动卖压证据更强，正值表示主动买盘证据
更强。UI 同时显示原始买量、卖量、未知量和覆盖率，不能只显示一个总分。

IEX 部分市场覆盖、缺少完整深度和免费数据延迟必须固定显示。该分数不进入 Ridge
或最终预测决策；后续只有通过点时回测后才能成为模型输入。

## UI

股票池每一行增加“实时”开关。页面顶部增加订阅管理器，显示：

- `固定 3 / 用户 N / 总计 N+3 / 30`；
- 采集器状态、IEX 标识和最后事件时间；
- 等待确认、断线、数据陈旧或市场休市状态；
- 当前用户订阅代码，可单独移除。

个股历史图附近新增独立实时卡片，保持固定高度，不改变日线图的横轴和布局。卡片
包含最近成交、买一/卖一/价差、1 分钟价格线、1 分钟成交量、买卖 Delta、压力条和
数据限制说明。

页面只轮询当前可见且已订阅的个股，每 2 秒请求一次；切换股票、隐藏页面或取消
订阅后停止无关轮询。所有字符串提供中英文翻译，按钮使用安全 DOM 属性和可访问
标签，不把 API 文本作为 HTML 插入。

## 安全与失败处理

- Alpaca key 只存在于采集进程环境变量，永远不返回浏览器；
- 浏览器只访问本地同源 Flask API；
- 写接口只接受 JSON 和规范化股票代码；
- SQLite 写入使用事务和 busy timeout；
- collector 未运行时仍可保存选择，但 UI 明确显示“等待采集器”；
- 数据库不存在或旧数据库尚未迁移时，GET 返回安全默认值；
- 单个实时请求失败不能清空已显示的最后有效数据；
- 不记录或返回 API secret、WebSocket 原始认证消息和本地文件路径。

## 验收

必须通过以下验证：

- 固定代码不可移除，用户上限为 27，替换操作原子且持久化；
- collector 不重启即可读取 revision 并热更新订阅；
- 请求代码、确认代码和等待代码状态准确；
- 纠错与撤销不会重复计入分钟 OHLCV 和成交量；
- 无报价成交保留为未知方向，压力分数显示覆盖率；
- 休市、陈旧、断线、未订阅和等待确认状态不会误显示为实时；
- UI 切换、取消订阅、页面隐藏时正确停止轮询；
- 实时卡片不导致日线图抖动、缩放或横向拖拽；
- 中英文、键盘操作和窄屏布局通过浏览器检查；
- 现有采集、股票池、个股分析和 Flask API 测试无回归。

## 非目标

本阶段不实现：

- SIP 全市场逐笔、完整 Level 2 深度或逐笔委托簿；
- 自动下单、仓位管理或券商账户操作；
- 用盘中压力覆盖 Ridge 预测；
- 将压力分数解释为上涨或下跌概率；
- 长期保存前端轮询结果的第二份数据库。
