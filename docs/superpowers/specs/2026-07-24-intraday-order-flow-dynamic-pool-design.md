# 免费盘中行情、动态订阅池与订单流评分设计

日期：2026-07-24
状态：设计已与用户逐段确认，待最终审阅

## 1. 背景

现有系统以 Tiingo 日线、VCP/动量/反转因子和逐日历史预测为主，已经支持：

- 在历史交易日上悬停并查看当日可得信息；
- 5、20、60 个交易日预测和滚动历史评估；
- 因子注册表、因子解释和中英文界面；
- K 线、成交量、趋势证据和预测覆盖层。

下一阶段需要用免费行情补充盘中买卖压力信息，并为以后接入 uSMART、Webull 等券商数据预留稳定接口。目标不是用不完整免费数据模拟完整交易所订单簿，而是在明确数据质量边界的前提下，研究以下问题：

1. 大盘、板块、个股是否处于上升或下降趋势；
2. 上升过程中何时出现抛压、买盘吸收或突破失败；
3. 下跌过程中何时出现恐慌、卖压吸收和反转确认；
4. 盘中信号能否改善未来 5/20/60 分钟和 1/5 日的收益或回撤预测；
5. 在任意历史时间点，预测、评分、解释与随后真实走势能否一致回放。

## 2. 设计原则

### 2.1 先保留原始事实，再计算因子

原始交易、报价和 K 线独立持久化。因子快照、综合评分和模型预测都是可重建的派生数据。增加或修改因子时，不应重新抓取已经保存的原始行情。

### 2.2 供应商能力显式化

统一接口不能假设每个数据源都有完整逐笔成交方向、盘口深度或历史回补。每个适配器必须返回能力声明和数据质量元数据；没有的数据降级计算，不能伪造。

### 2.3 严格时间点一致性

某个历史时间点的评分只能使用当时已经发生和已经发布的数据。动态订阅池、日线特征、板块特征、盘中订单流和预测都必须携带 `as_of`，回测中禁止用收盘后数据解释盘中信号。

### 2.4 展示分与预测概率分离

0–100 分用于让用户快速理解强弱，不解释成概率。模型使用未经合并的子因子，综合分只作为一个可选输入，并且必须与基线模型做增量比较。

### 2.5 交互覆盖层不参与布局

悬停产生的预测线、趋势线、标记和标签都绘制在固定坐标范围内的覆盖层中，不触发 autoscale、不扩展时间轴，也不改变 DOM 高度。鼠标向右移动只更新选中时间，不拖动或抖动图表。

## 3. 总体架构

数据流分为六层：

1. **供应商适配器**：Alpaca 免费行情优先；预留 uSMART 和 Webull；
2. **标准化事件层**：将不同供应商转为统一 Trade、Quote、Bar；
3. **原始存储层**：按供应商、标的、交易日保存不可变原始事件；
4. **特征层**：计算订单流、价量、趋势、板块和数据质量特征；
5. **评分与模型层**：生成可解释评分、滚动预测和评估；
6. **API 与界面层**：提供一体化研究看板和历史时间点回放。

建议新增的顶层模块边界：

```text
marketdata/
  base.py               # 接口、事件和能力声明
  alpaca.py             # 免费 IEX 适配器
  usmart.py             # 预留，未配置时不加载 SDK
  webull.py             # 预留，未配置时不加载 SDK
  normalization.py      # 时间、价格、成交方向标准化
  subscriptions.py      # 动态订阅池
  storage.py             # 原始事件与分钟聚合持久化

intraday/
  features.py           # OFI、VWAP、价量效率、吸收等子因子
  scores.py             # 六类可解释展示分
  snapshots.py          # point-in-time 因子快照
  evaluation.py         # 时间外回归、分类和稳定性报告
```

现有 `web/factors` 继续负责因子注册与说明；现有 `web/services/forecasts` 继续拥有预测版本和历史日期契约。新增模块通过服务层接入，不把数据抓取逻辑放进因子实现或路由。

## 4. 供应商接口与标准事件

### 4.1 接口

```python
class MarketDataProvider(Protocol):
    def capabilities(self) -> ProviderCapabilities: ...
    def stream_trades(self, symbols: Sequence[str], on_event) -> Subscription: ...
    def stream_quotes(self, symbols: Sequence[str], on_event) -> Subscription: ...
    def fetch_trades(self, symbol: str, start, end) -> list[TradeEvent]: ...
    def fetch_quotes(self, symbol: str, start, end) -> list[QuoteEvent]: ...
    def fetch_bars(self, symbols: Sequence[str], start, end, interval) -> list[BarEvent]: ...
```

`ProviderCapabilities` 至少声明：

- 实时或延迟；
- 覆盖市场，例如 IEX 或 SIP；
- 最大同时订阅标的数；
- 是否支持历史逐笔、历史报价、分钟 K 线；
- 是否提供供应商成交方向；
- 是否提供盘口深度和订单数；
- 当前权限或订阅不足的原因。

### 4.2 标准事件

所有事件使用 UTC 纳秒时间戳，同时保留原始供应商时间戳和本地交易日。

`TradeEvent`：

- provider、symbol、event_ts、received_ts；
- price、size、exchange、conditions；
- direction：buy、sell、neutral、unknown；
- direction_source：provider、quote_mid、tick_rule、unknown；
- source_sequence 或可用的去重键；
- session：pre、regular、post。

`QuoteEvent`：

- bid_price、bid_size、ask_price、ask_size；
- 可选 bid_order_count、ask_order_count、depth_level；
- crossed/locked/invalid 标记。

`BarEvent`：

- interval、start_ts、end_ts；
- OHLC、volume、trade_count、vwap；
- 是否由本地原始事件聚合。

标准化过程必须过滤非正价格/数量、明显乱序和重复事件，并记录丢弃计数。原始供应商载荷可以作为压缩 JSON 旁路保留，便于将来修正规则。

## 5. 免费阶段与动态订阅池

### 5.1 免费阶段范围

第一版使用 Alpaca 免费 IEX 流作为盘中来源，Tiingo 日线继续作为长期历史基础。IEX 只代表部分市场成交，因此 UI 和研究报告始终显示覆盖范围，不能把 IEX 订单流写成“全市场主力资金”。

若免费账户无法取得某类历史数据，系统只保存从启用日期开始采集的数据，不尝试用日线反推逐笔订单流。

### 5.2 30 标的动态池

订阅池按以下优先级生成：

1. 固定基准：SPY、QQQ、SOXX；
2. 当前界面选中的个股；
3. 同板块代表股，最多 16 只；
4. 用户观察列表和最新高风险/高机会候选，最多 10 只；
5. 去重后截断到供应商上限。

同板块代表股首先使用稳定的静态行业映射；以后可以替换为基本面分类服务。候选排序使用上一完整日或上一完整分钟已经可得的指标，不使用当前尚未完成 K 线。

订阅池只在以下事件改变：

- 用户切换当前标的；
- 定时刷新候选池；
- 连接恢复；
- 配置或观察列表改变。

图表悬停绝不修改订阅池，防止鼠标操作引起网络重订阅和界面漂移。切换标的时采用“先订阅新增、确认成功、再取消移除”的顺序，避免基准或当前标的短暂断流。

## 6. 存储与保留

第一阶段延续 SQLite，避免引入新的运维依赖：

- `provider_capability_snapshots`：供应商权限及覆盖快照；
- `subscription_intervals`：每只股票实际订阅起止时间；
- `trade_events`：标准化交易；
- `quote_events`：标准化最优买卖报价；
- `intraday_bars`：1 分钟聚合；
- `intraday_feature_snapshots`：每分钟子因子和数据质量；
- `intraday_score_snapshots`：六类展示分及版本；
- `intraday_forecasts`：模型、版本、起点、期限和预测；
- `intraday_outcomes`：预测到期后生成的真实结果。

唯一键优先使用供应商序号；没有序号时使用
`provider + symbol + event_ts + price + size + exchange + occurrence_index`。

默认保留策略：

- 标准化逐笔和报价至少保留 90 个自然日；
- 1 分钟 K 线、因子快照、评分、预测和结果长期保留；
- 任何清理都必须通过显式维护命令完成，运行服务不自动删除研究数据。

原始数据量增长后，可以将过期逐笔归档为按日压缩文件；该优化不改变仓库接口。

## 7. 成交方向与数据降级

### 7.1 方向推断

优先级如下：

1. 供应商明确给出的成交方向；
2. 成交价高于当时中间价视作主动买，低于中间价视作主动卖；
3. 成交价等于中间价或无同步报价时使用 tick rule；
4. 仍无法判断则为 neutral/unknown。

每个聚合窗口同时返回推断覆盖率，而不仅返回买卖量。低覆盖率时订单流分的置信度下降。

### 7.2 降级层级

| 层级 | 可用数据 | 可计算内容 | UI 标签 |
|---|---|---|---|
| A | 成交 + 报价/盘口 | OFI、主动买卖量、价差、深度、吸收 | 良好覆盖 |
| B | 成交 + 最优报价 | 主动买卖量、报价不平衡、VWAP、吸收 | 仅 IEX / 部分市场 |
| C | 仅成交 | tick-rule delta、成交效率、VWAP | 方向为推断 |
| D | 仅分钟 K 线 | 价量、影线、突破、波动 | 无逐笔订单流 |
| E | 数据断档 | 不计算该窗口 | 样本稀疏 / 数据不可用 |

数据质量包含覆盖分钟比例、成交方向覆盖率、报价年龄、事件延迟、断连时长和市场覆盖。低质量时评分向中性值收缩，而不是沿用最后一个高分。

## 8. 子因子定义

### 8.1 趋势子因子

市场、板块和个股使用相同方向但不同输入的标准化特征：

- 价格相对 EMA20、SMA50、SMA200；
- 均线斜率及多头/空头排列；
- 5、20、60 日和盘中动量；
- 相对强弱；
- 高低点结构；
- 当前价相对 VWAP 和开盘区间；
- 趋势中的成交量确认。

市场输入为 SPY/QQQ；半导体板块输入以 SOXX 为主并加入池内同行股广度；个股输入为当前标的。

### 8.2 上涨过程的抛压

“上涨抛压”表示上涨延续受到供应阻力，不等于下跌概率。组成包括：

- **价流背离**：价格创新高，但累计 delta、OFI 或推动效率不创新高；
- **买盘被吸收**：主动买成交较多，价格却难以上移；
- **高位拒绝**：上影线、突破后回落、收盘/分钟末回到 VWAP 或前高下方；
- **流动性转弱**：价差扩大、卖一量增加、买一量减少；
- **弱量突破**：突破时成交量或订单流确认不足；
- **跨层确认**：SOXX、QQQ 或同行股同时走弱。

### 8.3 下跌过程的承接和反转

下跌不直接标记为反转，而是状态机：

1. **恐慌卖出**：负 delta、放量、下破和波动扩张；
2. **卖压吸收**：主动卖出仍大，但价格不再创有效新低，低位下影、买方深度恢复；
3. **反转确认**：订单流由负转正、重新站上 VWAP/短均线、突破微观下降趋势或前一局部高点。

“不创新低”采用 ATR/盘中波动容差，避免相差一个最小报价单位就误判。只有第三阶段才显示“反转确认”；第二阶段显示“承接观察”，防止过早抄底。

## 9. 六类展示分

看板顶部固定展示：

1. 大盘趋势：0–100，越高越偏多；
2. 板块趋势：0–100，越高越偏多；
3. 个股趋势：0–100，越高越偏多；
4. 上涨抛压：0–100，越高表示上涨受阻越强；
5. 下跌承接：0–100，越高表示卖压被吸收越明显；
6. 订单流平衡：-100 至 +100，负值表示主动卖出占优。

每类分数由稳健分位数标准化后的子因子加权，并按有效权重重新归一。数据质量 `q` 低于 1 时向中性点收缩：

```text
0–100 分：display = 50 + q × (raw - 50)
-100–100 分：display = q × raw
```

评分响应包含：

- score、等级和一句话解释；
- 贡献最大的三个正向/负向子因子；
- 数据质量和缺失原因；
- 公式版本、因子版本、`as_of`；
- “展示分，不是概率”的固定说明。

建议阈值只是 UI 分级，不用于训练标签：

- 0–29：弱；
- 30–59：中性/观察；
- 60–74：较强；
- 75–100：强。

## 10. 一体化研究看板（方案 A）

### 10.1 布局

看板按以下顺序：

1. 顶部六张评分卡；
2. K 线与成交量；
3. 固定覆盖层中的历史预测线、抛压点、承接点和反转确认点；
4. 订单流平衡条和数据质量；
5. 风险解释卡；
6. 可展开的因子明细表。

每张评分卡带帮助图标，悬停或聚焦时显示：含义、主要输入、分数方向、数据来源和局限。

### 10.2 历史悬停

全页只有一个 `selectedTimestamp`：

- K 线命中某根柱后，将时间吸附到最近的有效历史点；
- 所有评分卡、解释、订单流、预测和表格使用同一快照；
- 日线与分钟线通过“截至该时间最后可知值”对齐；
- 点击可锁定，离开图表不清空；再次点击或按 Esc 解锁；
- 悬停末尾空白区不推进坐标轴，不重复请求订阅，不改变图表布局。

历史预测线的起点严格为选中时间，终点日期预先在数据坐标中计算。图表坐标范围在显示预测前已经确定；预测覆盖层不得调用 `fitContent()` 或修改可见逻辑范围。

### 10.3 冲突提示

系统不强行把所有信号压成一个结论。典型提示：

- `个股抛压 78（高）｜板块下跌确认 22（弱）`
  “个股顶部风险增加，但板块尚未确认。”
- `个股趋势 35（弱）｜下跌承接 74（较强）`
  “卖压出现吸收，等待站回 VWAP 或突破下降趋势确认。”
- `市场 28｜板块 31｜订单流 -66`
  “多层下行共振，若放量跌破最近低点，下跌风险增强。”

这些语句是规则化解释，不是投资建议或收益保证。

## 11. API 契约

现有股票详情响应保留兼容。新增内容放入版本化字段：

```json
{
  "intraday": {
    "as_of": "2026-07-24T14:35:00Z",
    "provider": "alpaca",
    "coverage": "iex",
    "quality": {},
    "scores": {},
    "top_contributors": [],
    "reversal_state": "absorption",
    "feature_version": "intraday-v1",
    "score_version": "order-flow-v1"
  }
}
```

建议新增：

- `GET /api/intraday/<ticker>?as_of=...`：当前或历史快照；
- `GET /api/intraday/<ticker>/series?start=...&end=...`：图表所需分钟序列；
- `GET /api/market-data/status`：供应商、订阅池、延迟和覆盖；
- `GET /api/intraday/evaluation`：时间外评估摘要。

缺失数据返回结构化 `unavailable_reason`，正常的数据不可用不使用 HTTP 500。

## 12. 建模和回归验证

### 12.1 预测目标

分别构造：

- 未来 5、20、60 分钟收益；
- 未来 5、20、60 分钟最大上涨/最大回撤；
- 未来 1、5 个交易日收益和最大回撤；
- 下跌事件、突破延续和反转确认的二分类标签。

盘中目标必须在规则交易时段内计算；跨日目标单独标记，不能把隔夜跳空混入纯盘中效果。

### 12.2 比较组

每个期限至少比较：

1. 日线价量/动量基线；
2. 基线 + 个股盘中子因子；
3. 基线 + 个股 + 板块/市场子因子；
4. 基线 + 全部子因子 + 数据质量交互项；
5. 仅综合展示分，作为可解释性对照而非推荐模型。

评估重点是新增因子的增量价值，不能只报告完整模型结果。

### 12.3 验证方式

- 按时间滚动训练、验证和测试；
- 同一交易日的样本不跨折；
- 股票分组稳健标准误或按日期 block bootstrap；
- 报告 AUC、Brier、校准、MAE、方向准确率和 top-k precision；
- 分年度、行情状态、标的、数据质量层级和板块分别报告；
- 对多因子检验做 FDR 控制；
- 记录系数/特征重要性的时间稳定性；
- 所有结论同时报告样本数和置信区间。

只有同时满足以下条件才进入生产评分：

- 时间外相对基线有稳定增量；
- 至少两个相邻期限方向一致；
- 不依赖单一年份、单一股票或极少数极端事件；
- 缺失/降级时行为可解释；
- 在交易成本和信号延迟敏感性测试后仍有价值。

如果订单流因子只在特定市场状态有效，保留为条件因子，并在 UI 中明确适用状态，不包装成通用信号。

## 13. 测试策略

### 13.1 单元测试

- 供应商载荷到标准事件的映射；
- 乱序、重复、锁盘/交叉报价和无效事件；
- quote-mid 与 tick-rule 方向推断；
- OFI、delta、VWAP、吸收、背离和状态机；
- 缺失权重重新归一及质量收缩；
- 动态池优先级、去重、上限和切换顺序；
- 严格 `as_of` 截断和无前视。

### 13.2 集成测试

- 模拟 WebSocket 断连、恢复、限流和部分订阅失败；
- 数据写入、重放和分钟聚合一致；
- 历史快照与当前快照 API 契约；
- Tiingo 日线与盘中分钟时间对齐；
- 未安装 uSMART/Webull SDK 时应用仍可启动。

### 13.3 浏览器回归

- 任意历史日期都能显示对应预测覆盖层；
- 鼠标向右移动不会拖动图表；
- 预测线出现/消失不改变图表尺寸、日期轴或滚动位置；
- 主图与成交量图十字线和日期一致；
- 中文/英文标签不遮挡日期；
- 评分卡、帮助说明、明细表与悬停时间一致；
- 断流和低质量标签醒目但不遮挡 K 线。

### 13.4 研究验收

用 NBIS 2026-06-30 及近期半导体相似场景作为解释性案例，但不把个别案例作为模型验收标准。生产采用全样本时间外指标和分市场状态稳定性作为验收依据。

## 14. 失败处理与可观测性

- WebSocket 断开后指数退避重连；
- 重连前后记录缺口，不把缺口两侧事件连续聚合；
- API 限流时保留已有数据并显示 stale，不清零成“无风险”；
- 写入失败进入有界内存队列，并记录 dropped event；
- 状态接口暴露 last event、last quote、延迟、订阅数、断连次数和缺口；
- 日志不输出 API 密钥、完整认证头或券商账户信息。

## 15. 分阶段落地

### 阶段 1：接口与离线重放

实现标准事件、能力声明、SQLite 表和因子纯函数；使用固定样本验证，无网络依赖。

### 阶段 2：Alpaca 免费采集与动态池

接入 IEX WebSocket、断线恢复、动态 30 标的池和状态接口，先积累数据。

### 阶段 3：评分与方案 A 界面

接入六类评分、帮助解释、质量标签、历史时间联动和固定预测覆盖层。

### 阶段 4：滚动回归

积累足够盘中数据后运行时间外比较；不稳定因子只保留在研究页。

### 阶段 5：券商适配器

在用户取得权限后实现 uSMART/Webull，利用供应商方向、盘口深度和订单数增强因子；保持 API、模型和 UI 契约不变。

## 16. 明确不做

- 不将 IEX 局部成交解释为全市场逐笔；
- 不把免费数据包装成完整 Level 2 订单簿；
- 不用未来数据重算历史悬停点；
- 不根据单只股票的一个成功案例直接上线因子；
- 不让鼠标悬停改变订阅池、图表范围或布局；
- 不在未验证前给出“必涨”“必跌”或交易保证。
