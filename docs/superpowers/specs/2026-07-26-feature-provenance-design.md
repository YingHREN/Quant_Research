# 点时特征来源与版本审计设计

日期：2026-07-26

## 目标

让每个预测日期使用的特征具备可复现、可审计的时间边界，避免把观察日之后才可获得的数据用于历史预测。

## 采用方案

API 使用“版本化特征目录 + 每个预测日期的快照引用”：

- 顶层 `feature_provenance_registry` 只返回一次特征目录，列出每个特征的名称、特征集版本、来源、时点语义和执行时点。
- 每个日期/周期的 forecast 只返回 `feature_provenance` 快照，包含目录引用、`observed_through`、`available_at`、`source_cutoff` 和内容寻址的 `data_version`。
- 日线 OHLCV 特征一律按美国东部时间正常收盘后可用；预测目标仍从下一交易日开盘开始。历史日期使用 `America/New_York` 时区计算，自动处理夏令时。
- `source_cutoff` 不得晚于观察日；`available_at` 必须与观察日同一美东交易日且不得早于 16:00。
- `data_version` 来自整个输入行情快照的稳定哈希，不暴露文件路径或供应商密钥。

这样既能逐项审计特征，又避免在每个日期重复几十份相同元数据。

## 特征目录

第一版覆盖 Ridge v4 的全部输入特征，并把它们按来源分为：

- 个股日线价格、均线、动量、波动率、成交量与结构形态；
- QQQ 大盘日线状态；
- 板块 ETF 日线相对强弱；
- 个股相对板块日线强弱；
- 日线买卖压力代理。

目录版本与特征版本独立。增删特征、改变公式、改变数据可用时间或来源，必须推进特征版本并使持久化 artifact 失效。

## API 与 UI

`/api/stocks/<ticker>` 顶层返回目录。历史日期模型输出携带快照引用。模型面板增加“数据时点”一组，显示：

- 特征可用时间；
- 数据截止日；
- 特征版本；
- 数据快照短版本；
- “收盘确认、下一交易日执行”的解释。

旧缓存缺少该字段时显示不可用，不猜测或补造版本。

## 验收

- 冬令时和夏令时日期均生成正确 UTC 偏移。
- 未来 source cutoff、过早 available_at、未知目录引用均被拒绝。
- 同一行情快照生成稳定 data version；修改任意 OHLCV 值会改变版本。
- 顶层目录只出现一次；每个 forecast 只携带快照引用。
- API、前端本地化、旧缓存降级与完整回归测试通过。
