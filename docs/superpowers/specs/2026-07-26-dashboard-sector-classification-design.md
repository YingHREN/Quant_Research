# 看板板块分类与筛选设计

## 目标

把独立研究库中的 SEC 基本面板块和 `market_behavior_v1` 交易行为板块接入现有看板，让用户能够：

- 按分类口径和板块筛选当前可分析股票；
- 看见研究池与当前可操作股票池的板块成员数量；
- 在选中股票的醒目位置同时查看两套分类、来源、置信度与冲突原因；
- 明确识别历史不足、数据库不可用或尚未分类的状态。

页面默认仍只加载现有轻量股票池，不读取 `data/research_prices.db` 中的 235 万行日线。

## 方案选择

### 采用：增强现有轻量股票池

新增只读分类服务，从研究库仅查询 `security_master` 和 `sector_classifications`。`/api/universe` 保持当前股票列表，在每行附加分类元数据，并增加全研究池分类汇总。

优点是页面加载轻、现有预测链路不变，且不会出现“股票能选择但分析服务没有价格”的半成品状态。

### 暂缓：直接开放全部 1,014 只股票

这需要市场数据仓库、预测缓存、因子计算和更新任务同时支持研究库按需读取，范围明显更大。当前只预留稳定接口，不在本阶段开放选择。

### 不采用：单独新建分类页面

会把选股筛选和个股决策拆散，用户需要来回跳转；现有左侧股票池已经是更自然的入口。

## 后端结构

新增 `ResearchClassificationService`：

- 使用单独的研究数据库路径；
- 只读打开 SQLite，不修改研究库；
- 按 ticker 批量返回分类，避免逐只查询；
- 统计 SEC 和行为板块成员数；
- 根据数据库文件时间戳做有界缓存；
- 数据库不存在、结构不完整或查询失败时返回 `unavailable`，不阻断原有股票池。

`UniverseSnapshotService` 接受可选分类服务，并为每个 ticker 增加：

```text
sector_classification:
  state: agree | conflict | sec_only | behavior_only | unclassified
  sec: {...} | null
  market_behavior: {...} | null
```

顶层增加 `classification_summary`，包含数据库观察日、研究池总数、各口径成员数和可用状态。

## 前端交互

左侧股票池增加：

- “分类口径”：SEC 基本面 / ETF 交易行为；
- “板块”：全部、11 个标准板块、未分类；
- 成员数量说明：研究池成员数与当前筛选后可操作成员数。

股票行显示当前分类口径对应的简短板块标签。证券标题区增加分类卡：

- SEC 基本面板块；
- ETF 行为板块与参考 ETF；
- 行为置信度和共同样本数；
- 一致、冲突或未分类状态；
- 冲突原因。

所有新增文案同时提供中文和英文，不把分类结果描述为投资建议。

## 性能与错误处理

- `/api/universe` 不查询 `daily_prices`。
- 分类查询使用 ticker 批量 `IN` 和汇总 `GROUP BY`。
- 分类库不可用时保持原股票池功能，只显示“分类不可用”。
- 过滤和排序在浏览器内完成，不触发重复行情请求。
- 未分类是正式状态，不回退猜测板块。

## 测试

- SQLite 小型夹具验证一致、冲突、单边分类和未分类。
- 验证数据库缺失时优雅降级。
- API 契约验证分类字段和汇总字段。
- JavaScript 验证按口径/板块过滤、排序和输入不可变。
- HTML、双语文案与安全 DOM 渲染测试。
- 最后运行完整 Python/Node 测试和本地浏览器视觉检查。
