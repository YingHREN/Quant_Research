# 前瞻向下风险影子评估设计

## 目标

把已经通过历史走步研究门槛的向下风险候选放入真正的前瞻留出期。
系统从冻结日之后才开始记录预测，不允许把已经看过的历史日期回填成
“影子成绩”。当未来 5、10、20 个交易日的路径成熟后，再用次日开盘
执行口径评估覆盖率、分类质量和交易风险，但不改变线上 Ridge、
TOPRISK 或 `forecast_decision_policy`。

本项目同时为统一走步 runner 增加阶段进度和耗时，使全量研究能够区分
数据加载、模型训练、规则上下文、对齐评估和报告发布的成本。

## 冻结边界

首个实验版本为 `downside-shadow-v1`，冻结条件如下：

- 冻结市场日期是创建实验时研究数据库中所有必要参考数据共同可用的
  最新交易日；当前预期为 `2026-07-24`。
- 可记录的观察日必须严格晚于冻结市场日期。冻结日及更早日期一律拒绝，
  即使数据库后来补齐或修订也不能回填。
- 固定 240 只研究股票队列。参考指数和板块 ETF 只提供上下文，不作为
  被评估股票。
- 固定特征列表、预处理参数、模型系数、方向阈值、风险规则版本和模型
  源码指纹。改变任何一项必须建立新的 `experiment_id`，不能覆盖 v1。
- 压力期专用 Logistic 只评估 5 日和 20 日；12 项记忆风险单独评估
  5/10/20 日；通用 Logistic 作为三个期限的统计对照；Ridge 保留基线。
- 压力专用模型只在 `under_pressure`、`correction` 或
  `acute_selloff` 环境产生可用输出。其他环境记为“不适用”，不得当成
  阴性预测。

## 冻结模型产物

新增纯研究模块负责从冻结日前可用的成熟标签拟合最终影子模型：

1. 使用统一 v2 相同的次日开盘标签和固定 5/10/20 日阈值。
2. 每条训练标签的结束日期必须不晚于冻结市场日期。
3. 中位数填充、缩放参数、特征顺序、Logistic 系数、截距和事件阈值
   全部写入版本化 JSON 产物。
4. JSON 产物保存训练样本数、训练标签最晚结束日、训练股票队列、
   数据库内容指纹、代码提交和 SHA-256 校验值。
5. 加载时严格校验 schema、有限数值、特征顺序和 checksum；失败时
   停止记录，不用现场重训结果替代冻结模型。

模型产物位于 `reports/downside-shadow-v1-model.json`。它是可复核研究
产物，不是线上模型缓存。

## 只追加影子账本

使用独立 SQLite 文件 `data/downside_shadow.db`，不写入行情库或
`analysis_cache.db`。

### `shadow_experiments`

一行定义一个不可变实验：

- `experiment_id`
- `study_version`
- `created_at`
- `frozen_market_asof`
- `universe_json`
- `horizons_json`
- `model_artifact_path`
- `model_artifact_checksum`
- `database_fingerprint`
- `code_commit`
- `status`

相同 `experiment_id` 的不可变字段不一致时拒绝启动。

### `shadow_predictions`

每个 `experiment_id × specification × ticker × observation_date ×
horizon` 最多一行：

- 原始布尔事件、连续分数、可用状态和不可用原因；
- 当日市场状态与点时分组；
- 模型版本、规则版本、特征版本；
- `available_at_close`、`executable_at=next_session_open`；
- 行情内容签名、记录时间和 payload checksum。

相同主键且 payload 完全一致时允许幂等重试；任何字段冲突都拒绝覆盖。
不能 UPDATE 或 DELETE 已记录的预测。

### `shadow_outcomes`

预测成熟后写入一次：

- 实际入场日和入场开盘价；
- 标签结束日、终点收益、MAE、MFE 和向下事件；
- 成熟时间、行情内容签名和 checksum。

已有 outcome 只有在 payload 完全相同时才允许幂等重试。行情后续修订
造成冲突时保留原行并记录审计错误，不能静默改写成绩。

## 每日流程

CLI `research/run_downside_shadow.py` 提供三个明确动作：

1. `freeze`：创建实验和冻结模型产物。只允许在实验不存在时执行。
2. `capture`：读取最新共同可用交易日；若日期严格晚于冻结日且尚未记录，
   用冻结模型和冻结规则生成一次预测快照并原子写入账本。
3. `evaluate`：只为未来窗口完整的预测写入 outcome，随后原子生成 JSON、
   CSV 和中文 Markdown 报告。

`capture` 不自动追补遗漏的历史日期。若某天没有在当日数据状态下记录，
账本明确显示缺口。首版通过 CLI 手动或外部定时任务调用，不接入网页请求，
也不让行情更新因影子任务失败而失败；接入更新任务另行设计。

## 评价口径

报告同时展示：

- 计划观察日、实际捕获日、缺口数、股票覆盖率和模型可用率；
- 5/10/20 日事件率、信号率、精确率、召回率、特异度、平衡准确率、
  F1、ROC AUC 和 PR AUC；
- 非重叠样本结果，以及半导体、软件与云服务、其他组和市场状态分层；
- 从信号到路径首次越过阈值的提前交易日数；
- 未触发信号样本的机会成本；
- 以次日开盘为入场、固定期限为退出的信号组合收益和最大回撤。

概率指标仅用于有连续概率分数的 Logistic。二元规则不生成伪造的 AUC
或校准结果。样本不足 50 或只有一个实际类别时返回 `insufficient`。

## 晋级条件

影子实验至少满足以下条件才允许提出下一阶段评审：

- 最少覆盖 60 个实际捕获交易日；
- 5 日和 20 日各至少 1,000 个成熟压力期样本；
- 半导体和软件与云服务各至少 250 个成熟样本；
- 压力专用 Logistic 在两个期限的平衡准确率均高于同池 Ridge；
- 两个期限的召回率均不低于 0.45，特异度均不低于 0.55；
- 相对 Ridge 的最大回撤不恶化超过 2 个百分点；
- 无预测回填、冲突覆盖、未来数据泄漏或模型产物校验失败。

达到这些门槛只允许进入人工评审，不能自动获得线上否决权。

## 统一 runner 进度与耗时

`run_unified_downside_benchmark.py` 使用 `time.monotonic()` 记录并输出：

- `load_inputs`
- `build_statistical_predictions`
- `build_rule_context`
- `label_and_align`
- `evaluate`
- `publish`
- `total`

进度写入 stderr，结构化秒数写入 manifest 的 `stage_timings_seconds`。
耗时字段不参与研究身份或模型成绩，不改变原子报告发布规则。

## 失败处理

- 数据库不存在、参考数据不齐、冻结产物损坏、日期倒退或 checksum 冲突
  均失败关闭，不产生预测。
- 冻结实验记录的产物绝对路径因 worktree 搬迁而不存在时，`capture` 和
  `evaluate` 可以读取命令行显式指定的产物，但必须通过实验中已冻结的
  SHA-256 校验；不得修改实验身份、接受 checksum 不同的替代文件，或对
  其他读取/内容错误静默回退。
- 事务失败时不留下部分股票或部分模型记录。
- 单个模型在合法输入下不可用时保存明确原因；模型异常则整日 capture
  回滚，避免形成看似完整的部分快照。
- 输出和日志不能包含 API key、Secret 或完整环境变量。

## 测试与验收

- 冻结日及更早日期无法写入预测。
- 未来追加数据不改变任何旧预测；相同捕获幂等，冲突捕获失败。
- 冻结模型的训练标签结束日全部不晚于冻结日。
- 只有完整未来窗口才能写 outcome；结果使用次日开盘。
- 规则缺失保持 unavailable，不自动变成 False。
- SQLite 事务失败不留下部分行。
- 报告明确显示 `online_authority=none` 和实际捕获缺口。
- 统一 runner 的每个阶段都有非负耗时，总耗时不小于任一阶段。
- 现有全量测试继续通过，网页服务和生产决策代码不发生行为变化。
